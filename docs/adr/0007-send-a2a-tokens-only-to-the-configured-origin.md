# 0007. A2A のトークンは、設定した URL と同じオリジンにだけ送る

- ステータス: Accepted
- 日付: 2026-11-08
- 関連: ADR 0006、PR #3 の CodeRabbit の指摘(`src/infrastructure/a2a.rs`)

## 状況

A2A のクライアントは、設定した URL からエージェントカードを取り、カードの `supported_interfaces` が広告するエンドポイントに `send` などを送る。トークンは `reqwest::Client` の `default_headers` に入っているので、カードが別オリジンの URL を広告すると、そこへトークンが送られる。

実装前に、次を `a2a-rust` 0.1.0 と `reqwest` 0.12 のソースで確認した。

- `resolve_interface_url` は、絶対 URL ならそのまま使い、相対 URL なら設定した URL を基準に解決する。オリジンの検査は無い。
- `send_message`、`get_task`、`cancel_task`、`subscribe_to_task` は、カードから選んだエンドポイントに、同じクライアント(同じ既定ヘッダ)で送る。カードはクライアント内に 5 分キャッシュされ、以降の送信先の選択と同じものが使われる。
- リダイレクトは `reqwest` の既定(最大 10 回)に従う。`reqwest` は、別オリジンへのリダイレクトで `Authorization` を外す(この挙動は今回テストしていない。ドキュメントと実装の記述による)。

## 決定

点数化せず、ユーザーが選んだ。

- トークンがあるとき、`send`、`task get`、`task cancel`、`task watch` の前にカードを取り(キャッシュを使う)、JSON-RPC と HTTP+JSON のエンドポイントがすべて設定した URL とオリジン(スキーム、ホスト、ポート)が同じかを調べる。違えば、送る前にエラーで終了する(終了コード 1)。
- `card` は設定した URL にしか送らないので、検査しない。
- 別オリジンを信頼するための設定は置かない。必要なら、設定の `url` を広告されるオリジンに合わせる。
- 利用しないバインディング(gRPC など)は検査しない。

選ばれなかった案: `trusted_origins` を設定に足して別オリジンを許す(B)。

## 結果

- 良い点: カードを改ざんまたは誤設定されても、トークンは設定した送信先から出ない。
- 代償: カードが設定と別オリジンを広告する正規のエージェントには、`url` を合わせるまで使えない。トークンを使う `send` などで、カード取得が1回増える(キャッシュにより、続く送信では増えない)。
- 見直す条件: 別オリジンの正規エージェントを使う要望が出たとき(`trusted_origins` を検討する)。
