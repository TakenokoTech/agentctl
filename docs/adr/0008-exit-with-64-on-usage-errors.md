# 0008. コマンドラインの使い方が誤っているときは、終了コード 64 で終わる

- ステータス: Accepted
- 日付: 2026-11-08
- 関連: PR #3 の CodeRabbit の指摘(`src/main.rs`)

## 状況

`Cli::parse()` は、使い方が誤っているとき(未知のサブコマンド、引数の不足など)に終了コード 2 で終了する。一方 `agentctl` は、2 を「ツールのエラー、または task の失敗」に割り当てている。呼び出し側のスクリプトや AI エージェントは、2 を見ても「呼び方が悪い」のか「ツールが失敗した」のかを区別できない。区別できることが `agentctl` の特徴(`docs/index.md`)であり、現状はそれと矛盾する。終了コードは公開インターフェースである。

## 決定

点数化せず、ユーザーが次の選択肢から選んだ。

- 使い方の誤りは、終了コード 64(sysexits の `EX_USAGE`)で終了する。
- `Cli::try_parse` を使い、`--help` と `--version` は 0 のままにする。エラーメッセージは clap の出力をそのまま stderr に出す。
- 終了コードの対応は `presentation::usage_exit_code` に置く。
- `docs/manual/reference.md`、`docs/index.md`、`docs/ja/index.md`、`--help` の説明を更新する。

選ばれなかった案: 2 のままにして docs に明記する(A)。使い方の誤りを 1 に寄せる(B。設定や通信のエラーと区別できない)。

## 結果

- 良い点: 0、1、2、64 で「成功」「呼び出せなかった」「ツールが失敗した」「呼び方が悪い」を区別できる。
- 代償: 使い方の誤りで 2 を期待していた既存のスクリプトは、64 に合わせる必要がある。
- 見直す条件: 64 が他の取り決めと衝突する環境が見つかったとき。
